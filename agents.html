1. 專案目的與讀者

這是一個給大學生閱讀的金融入門網站。我希望把常見觀念整理成能理解、能計算，也能辨認誤解的短篇筆記。網站使用台灣繁體中文，語氣自然、清楚，從生活問題切入，再交代公式與限制。

新增或修改本專案前，先閱讀本文件，再檢查實際檔案。本文件描述的規則必須與網站一致；修改結構時，同步更新受影響的文件與測試。

2. 技術與檔案位置

  • 使用 HTML、CSS、原生 JavaScript；網站瀏覽不需 API、登入、金鑰或外部套件。
  • index.html：共用頁面外框、首頁、概念清單、關於專案及文章容器。
  • styles.css：所有版面、色彩、字級、響應式與焦點樣式。
  • content.js：所有文章資料；指定 window.FINANCE_LESSONS 陣列。
  • math.js：複利計算與輸入驗證，供網頁和 Node 測試共用。
  • app.js：資料呈現、搜尋、分類、文章切換、自我檢核與試算互動。
  • tests/check.mjs：資料格式、公式結果、輸入邊界、內部資源與必要規則檢查。
  • scripts/documents.mjs：以 AGENTS.md、README.md 產生 agents.html、readme.html，只更新這兩份閱讀頁。
  • agents.html、readme.html：公開文件的閱讀頁，不手動修改正文；修改 Markdown 後重新產生。
  • scripts/build.mjs：確認閱讀頁與 Markdown 一致，再把網站需要的確切檔案複製到 dist/，不修改來源。
  • README.md：專案簡介、功能、執行方式及實際延伸紀錄。
  • dist/：發布產物，由建置產生，不手動修改。GitHub Pages 也可直接發布根目錄的 index.html。
  • scripts/document-template.html：兩份文件閱讀頁共用的原版版型；只在調整文件版型時修改。
  • .nojekyll：GitHub Pages 的靜態網站設定，保留此空白檔案。

檔名採小寫英文及連字號。新增文章通常只修改 content.js；不得為每篇複製一套 CSS、頁面模板或互動程式。

3. 視覺與閱讀結構

  • 主色為深綠，搭配米白背景、淡綠重點及少量暖橘提示。使用系統字型，維持文字對比與明顯的鍵盤焦點。
  • 首頁依序為專案介紹、概念清單、學習方式、關於專案。文章卡片保留編號、分類、標題、摘要與閱讀連結。概念清單後的持續整理提示獨立呈現，不當成文章，不加入篇數、搜尋結果或文章資料；只有全部分類且搜尋空白時顯示。
  • 正文以桌機 17px、窄螢幕 16px 為基準；首頁摘要與說明使用 16px。導覽、表單、必要註解至少 14px；分類、篇數與頁尾使用 12～13px，英文輔助眉題可用 11～12px。放大文字時同步調整留白與換行，不把必要說明縮成難以閱讀的小字。
  • 每篇固定依序呈現：生活問題、核心直覺、公式與符號、自編例子、常見誤解、自我檢核、參考來源。
  • 電腦版可使用側邊章節導覽；手機版保持單欄閱讀，不以縮小整頁或水平捲動處理內容。
  • 表格放在可水平捲動的獨立容器，其他內容不得超出畫面。按鈕、表單與連結必須可用鍵盤操作。
  • 視覺必須幫助理解；圖表或數值示意須與計算相符，不放無關裝飾圖片。
  • 公開頁面、文件、網頁描述與下載檔案只以作者姓名署名，不列學校、系級、學號或其他交件身分資料。完整課程身分資料僅填於 NTU COOL，不加入公開原始碼或測試範例。

4. 文章資料格式

content.js 中每筆文章須具有下列欄位；新增欄位前需同步修改使用它的程式、本文與測試。

欄位格式與規則
id唯一的小寫英文連字號識別碼；須與 ^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$ 相符
order唯一的正整數；首頁依此排序
category時間與價值、風險與配置、債券入門 擇一
title、subtitle、summary、question非空白字串；摘要簡短，生活問題應可引出核心機制
intro至少兩段非空白字串，先說直覺，再說推理或適用限制
takeaway一句能帶走的核心結論
formula包含 expression 字串、symbols 陣列（每筆有 symbol、meaning）、assumptions 非空字串陣列
example包含 intro、headers、rows、conclusion、note；每一列欄數須與表頭相同，並明示自編或假設情境
mistakes至少兩筆 { myth, fact }，逐一說清楚錯在哪裡
quiz包含 question、恰好四筆 options（每筆有 text、explanation），以及整數 answer（0 到 3）
sources至少一筆 { publisher, title, url, supports }；使用已核對的 HTTPS 一級來源，說明支持範圍
interactivecompound 或 none；只有適合單筆複利的文章使用 compound

窄螢幕可在表格內左右滑動。

所有文字欄位只存純文字，不存 HTML、腳本、事件處理器或 Markdown。呈現時必須以文字節點或安全的轉義處理，禁止直接執行文章內容。

5. 內容與計算規則

  • 優先使用官方教育資料或原始教材，保留機構、標題、網址與支持的觀念。來源只提供依據，正文使用自己的說明，不抄寫段落。
  • 所有自編數值、機率與案例明確標為教學假設；不得寫成真實行情、個人操作經驗或保證報酬。
  • 先解釋符號及期間，再使用公式。百分數顯示為 %，計算時轉為小數；利率期間與期數必須一致。
  • 金額使用 NT$ 與千分位；計算過程保留精度，顯示至小數點後兩位，整數可省略小數。
  • 單筆複利使用 FV = PV × (1 + r)^n，並說明利息留存、沒有額外投入或提領及忽略稅費。
  • 期望報酬為機率加權平均；機率合計須為 1，不能把平均結果當成保證結果。
  • 固定利率債券的價格與市場要求報酬率反向，須加上其他條件不變的前提；票息與市場利率須明確區分。
  • 分散效果取決於資產共同變動，不能聲稱分散可以保證獲利或消除所有風險。
  • 不加入個別商品推薦、交易指令、即時行情、會員或付費功能。

6. 互動行為

  • 首頁搜尋同時比對標題、摘要與分類，可與分類篩選合併；沒有結果時顯示清楚訊息及重設操作。
  • 文章使用 #lesson/<id> 切換；重新整理、直接進入網址與瀏覽器上一頁都應維持正確內容。找不到文章時提供返回概念清單的連結。
  • 自我檢核先選四個選項之一，再按確認；提交前不公布答案。提交後指出正確選項並解釋各選項，可重新作答。
  • 複利試算的本金範圍為 0 至 100,000,000；年利率範圍為 -50% 至 50%；年數為 0 至 50 的整數。空白、非有限數值與超出範圍的輸入須顯示錯誤並隱藏舊結果。
  • 試算的 0% 利率、0 年與 0 本金須正常運算；負報酬顯示損失。輸入不會傳到伺服器，不儲存個人資料。

7. 新增一篇內容的流程

  1. 先檢查現有資料格式、分類與識別碼，確認新主題不重複。
  2. 核對來源，設計能自行驗算的例子和一題四選一，完整填寫第 4 節欄位。
  3. 在 content.js 加入一筆新資料，保留既有文章的 id、順序與正確內容。若只新增同型內容，不改頁面模板。
  4. 若修改 Markdown，先執行 node scripts/documents.mjs 同步閱讀頁。再執行 node tests/check.mjs 與 node scripts/build.mjs；失敗時先修正原因，不以刪除檢查或改寫預期值掩蓋問題。
  5. 在瀏覽器檢查新文章、首頁排序與數量、搜尋、分類、前後篇導覽、四選一回饋及參考來源；也抽查既有文章與手機畫面。
  6. 依實際完成情況更新 README.md 的延伸紀錄；未執行的檢查不能寫成已通過。

8. 完成標準與修改範圍

文章內容、網站呈現與本文件須互相一致。交付前，重新讀取最終檔案並確認語法、來源連結格式、計算、互動與發布檔案。瀏覽器測試與靜態測試分開記錄。

首頁的文件入口使用含 UTF-8 宣告的 HTML 閱讀頁，保留章節導覽、標題、清單與表格，並提供 Markdown 原始檔下載。Markdown 使用 UTF-8 編碼，開頭保留單一 BOM 編碼標記，避免瀏覽器誤判中文編碼。文件使用標題、段落、清單、表格及行內程式碼；需要其他格式時，先更新閱讀頁產生方式與檢查。發布前需實際開啟首頁及兩份閱讀頁，檢查文字、連結與窄螢幕版面，不能只確認檔案存在。

新增或修正只修改本專案內的必要檔案；不改其他專案、不刪除既有內容、不寫入密碼或 API 金鑰。發布狀態與 GitHub 上傳狀態依實際結果記錄，尚未完成時保持明確。
